# 기술 문서

어나더 코드 R 한글 패치가 어떤 파일을 어떻게 바꾸는지 정리한 문서입니다. 유럽판 `RNOP01`에 일본판 `RNOJ01` 원문 기준 번역을 넣습니다.

## 왜 유럽판에 넣나

- 일본판은 장 제목 영상 9개(`THP/chap01~09.thp`)에 일본어 글씨가 박혀 있습니다. 유럽판은 같은 장면에서 영상 위에 이미지(`LANG/ENG/LYT/MOV/CHAPTER_0x.ARC`)를 띄우므로, 영상을 다시 인코딩하지 않고 이미지만 바꾸면 됩니다. 오프닝 날짜·장소 자막(`TITLE_LOGO.ARC`의 `opTEXT_*`), 엔딩 이름(`ENDING_01/03.ARC`)도 같습니다.
- 유럽판은 언어별 자산이 `LANG/<언어>/`에 나뉘어 있어 영어 폴더(`LANG/ENG`)만 바꾸면 됩니다. 본체 언어를 한국어로 두면 영어 폴더가 선택됩니다.
- 두 판의 대사 파일(BMG 83개)은 메시지 개수가 1:1로 같아서, 일본어 원문 기준 번역을 메시지 번호로 대응시킬 수 있습니다.
- 유럽판도 60Hz(EuRGB60)로 동작하고 영상은 29.97fps로 일본판과 같습니다.

## 원본 배치 유지 ISO (`tools/inplace.py`)

**wit으로 파일 트리를 새로 묶으면 게임이 멈춥니다.** 원본 디스크는 파일을 32바이트 경계에 놓고 사이를 0으로 채우는데, wit은 4바이트 간격으로 붙입니다. 게임은 파일을 32바이트 단위로 읽고, 유럽판 `LANG/*/SCRIPT/MEMORY.dat`는 끝에 개수 두 개(0, 0)가 빠져 있어 파일 뒤를 읽습니다. 새로 묶은 디스크에서는 다음 파일의 바이트를 개수로 읽어 메모리 할당에 실패하고 주소 0에 씁니다(Dolphin: `Invalid write to 0x00000000, PC=0x8010ecbc`). `--align-files`도 32KB 이상 정렬에만 적용되어 해결되지 않습니다.

그래서 원본 ISO를 복호화한 뒤 바뀐 파일만 제자리에 덮어쓰고(커진 파일은 파티션 안 빈 공간으로 옮기고 FST를 고침), 바뀐 2MB 그룹의 H0/H1/H2 해시를 다시 계산하고, 암호화한 뒤 H3 표와 TMD를 고쳐 가짜 서명합니다. 번역한 `MEMORY.dat`에는 빠진 개수 두 개를 채워 넣습니다.

FST에는 Shift-JIS 파일 이름(`PUZZLE_MESS１.BMG` 등)이 있습니다. wit 추출본에서는 이 이름이 latin-1로 풀려 있어 되돌려 맞춥니다.

## 배포용 파일 단위 패처 (`tools/make_patcher.py`, `patcher/`)

ISO 통째 xdelta는 원본 ISO가 바이트 단위로 같아야 적용됩니다. 그런데 이 게임의 개발용 덤프만 해도 업데이트 파티션이 빠져 있어(파티션 표에 DATA 하나, 0x50000부터 0), 정본 덤프를 가진 사람에게는 맞지 않습니다. 그래서 바뀐 게임 파일 303개마다 원본과의 xdelta 차분만 배포합니다.

사용자 PC에서 `patch.ps1`이 하는 일:
1. `wit extract --psel data,update --pmode name`으로 게임 파티션을 `_work/DATA`, 업데이트 파티션(있으면)을 `_work/UPDATE`에 풉니다.
2. 파일마다 원본 MD5 확인 → 차분 적용 → 결과 MD5를 확인합니다.
   - xdelta3는 제어 문자가 섞인 파일 이름(`PUZZLE_MESS\x82P.BMG`)을 열지 못해 임시 이름으로 복사해 적용합니다.
3. 업데이트 파티션이 없으면 게임 파티션의 `boot.bin`·`bi2.bin`·`apploader.img`·`main.dol`·티켓·TMD로 빈 업데이트 파티션(약 4MB, 오프셋 0x50000)을 만듭니다.
   - UWUVCI의 영상 모드 패치(PAL to NTSC)는 풀린 이미지의 `DATA\sys`에 `wii-vmc.exe`를 넣습니다. 파티션이 하나뿐이면 `DATA\` 접두어 없이 풀려서 이 단계가 경로 오류로 실패합니다.
   - 영상 모드 패치를 끄면 파티션 하나짜리도 주입됩니다(사용자 확인). 이 게임은 원래 60Hz라 끄는 것을 권합니다. 업데이트 파티션은 이 옵션을 켠 경우를 위한 보험입니다.
4. `wit copy`로 DATA와 UPDATE를 함께 묶습니다.

wit으로 다시 묶으면 파일 배치가 4바이트 간격이 됩니다(7,049개 중 6,610개가 32바이트 경계에서 벗어남). 멈춤의 원인이던 영어 `MEMORY.dat`는 번역본에서 빠진 개수 두 개를 채웠습니다. 다른 언어 폴더의 `MEMORY.dat`는 언어 분기를 영어로 고정해서 읽히지 않습니다.

## 대사 (BMG, `tools/bmg.py`, `tools/insert_bmg.py`)

- 형식: `MESGbmg1`, 인코딩 UTF-8. INF1(항목 8바이트: DAT1 안 위치 4 + 속성 4) + DAT1. MID1 없음(메시지 번호 = 파일 안 순번).
- 태그: `1A` + 길이(1A 포함) + 그룹(1) + 종류(2) + 자료. 태그 안에 `0A`·`00` 바이트가 있으므로 줄바꿈·NUL로 나눌 때 태그를 건너뛰어야 합니다.
  - 그룹 00 종류 0001: 대화창 넘김
  - 그룹 00 종류 000D: 화자 이름(앞에 제어 바이트, 뒤에 이름). **유럽판도 일본어 이름(アシュレイ 등)을 그대로 씀 = 게임 내부 키라 번역하지 않음**
  - 그룹 FF 종류 0002: 루비(덮는 글자 수 1 + 읽기)
- 넣는 방식: 메시지마다 유럽판 대화창 수·화자 순서가 일본판과 같으면(약 98%) 유럽판 구조를 두고 창마다 한국어 줄을 넣습니다. 다르면(유럽판 현지화에서 대사를 다시 나눈 곳) 일본판 메시지 구조에서 루비 태그만 빼고 넣습니다. 같은 엔진이라 태그가 호환됩니다. 유럽판에서 비어 있는 메시지(줄거리 더미 등)는 건드리지 않습니다.
- 창 안에서는 글이 있는 줄 순서대로 한국어 줄을 넣고, 한국어 줄이 더 많으면 마지막 글 줄(태그 포함)을 복제해 늘립니다.

## 폰트 (BRFNT, `tools/brfnt.py`, `tools/font_ko.py`)

- 유럽판 영어 폴더의 `FONT_A`, `FONT_A_21`, `FONT_B`, `FONT_B_16`(각 215칸, IA4)에 KS X 1001 한글 2,350자와 기호 15종을 더합니다. 합계 약 6.7MB로 일본판 폰트(약 4.5MB)보다 크지만 메모리 문제는 없었습니다.
- 새 글자는 새 시트부터 채우고, 글자 폭(CWDH)은 하나뿐인 구역을 늘리고, 글자→칸 대응은 **기존 scan CMAP(0000~FFFF)에 합칩니다.** nw4r은 범위가 맞는 첫 CMAP에서 멈추므로 뒤에 새 CMAP을 달면 읽히지 않습니다.
- 모양: 맑은 고딕 Bold, 흰 글자 + 검은 1px 테두리(원본 영어와 같은 방식). 한글은 모든 글자를 같은 자간(FONT_A 계열·FONT_B 16px, FONT_B_16 15px)으로 둡니다. 글자마다 보이는 폭으로 자간을 주면 넓은 글자가 옆 글자에 붙어 보입니다.

## 기타 텍스트 (`tools/insert_mess.py`)

공통 형식은 개수(u32) + 레코드 위치 표 + 레코드이고, 문자열은 u32 길이 + UTF-8 본문(끝 NUL)입니다.

- `CHARA.MESS`, `ITEM.MESS`, `HISTORY.MESS`, `PUZZLE_TXT_*.MESS`, `GPMESS_DATA.STR`, `ICOMB.COMB`: 일본판과 유럽판을 같은 규칙(길이 칸 + 끝 NUL + 태그 밖 NUL 없음)으로 읽어 레코드 틀(숫자 4바이트 / 문자열)이 같은지 확인하고, 문자열만 바꾸고 위치 표를 다시 씁니다.
- `MAIL.MESS`, `PUZZLE_MAIL_*.MESS`: 레코드 = 길이 3개 + 문자열 3개(보낸 사람·제목·본문 / BGM 이름·곡명·설명).
- `SCRIPT/MEMORY.dat`(기억 퀴즈): 개수 + (번호, 길이, 질문, 선택지 개수, 선택지…) + 끝 개수 두 개. 유럽판에 빠진 끝 개수를 채웁니다.
- `HISTORY.MESS`, `GPMESS_DATA.STR`은 유럽판 영어 폴더에도 일본판과 똑같은 파일이 들어 있습니다(유럽판은 쓰지 않는 것으로 보임). 해가 없으니 한국어로 넣습니다.
- 퍼즐 Z008(얼굴 인증) 문구는 일본판에서는 그림이지만 유럽판은 `PUZZLE_TXT_008.MESS` 텍스트로 표시합니다.

## main.dol (`tools/patch_dol.py`)

- **GPMESS 사본**: `GPMESS_DATA.STR`과 같은 형식의 문자열 묶음(획득 문구, 장 이름, 세이브·오류 문구 136개)이 실행 파일 안에 있습니다. 일본판은 `0x2cd4c0`, 유럽판은 5개 언어 사본이 이어져 있습니다(영어 `0x2f3f40`~). 코드(`0x8008d6fc`~)가 언어 번호로 영어 사본 주소 + `0x1500`/`0x2b38`/`0x42e0`/`0x5a04`를 고르므로, 이 더하는 값 4개를 0으로 바꾸고 한국어 사본을 영어 자리부터 다섯 칸 전체 공간에 씁니다. 모든 언어 설정이 한국어가 됩니다.
- 아이템 획득 문구는 유럽판이 앞붙임("Acquired: " + 아이템)이라 번역도 앞붙임("획득: ")으로 맞췄습니다(일본판은 뒤붙임).
- **장소 이름 136개**: 유럽판 `0x331b08`부터 언어별 목록(개수 + 길이·문자열) 5개가 이어져 있습니다. 직접 가리키는 주소가 코드에 없어 앞에서부터 차례로 읽는 것으로 보고, 영어 자리에 한국어 목록을 쓰고 나머지 4개 언어는 빈 문자열 목록으로 줄여 뒤에 잇습니다.

## 이미지 (`tools/insert_tex.py`, `tools/gxtex.py`, `tools/gxenc.py`, `tools/u8.py`)

- 컨테이너: U8 묶음(`.ARC`, `.acrarc`, 무압축) 안의 TPL, BRRES(TEX0). 형식은 I4·I8·IA4·IA8·RGB5A3·RGBA8·CMPR.
- 번역 대상 찾기: 일본판 이미지 20,213개를 유럽판(영어 폴더 우선)의 같은 경로와 해시로 비교해 다른 것과, 유럽판이 영어 폴더에서 묶음째 바꾼 곳의 일본판 이미지를 눈으로 검토해 일본어가 있는 것만 골랐습니다. 일본판도 영어인 문서·간판은 제외했습니다.
- **레이아웃 묶음(LYT)은 일본판 묶음을 통째로 가져와** 한국어 이미지를 크기 조정 없이 넣고 유럽판 영어 폴더 자리에 씁니다. 유럽판은 영어에 맞춰 레이아웃을 바꿔 둔 곳이 많습니다(타이틀의 A 버튼 위치, 인물 소개 카드의 현지 이름 창 삭제, 지도 말풍선 폭). 한국어 이미지는 일본판 크기·배치에 맞춰 만들었으므로 일본판 레이아웃이 맞습니다.
  - **유럽판 묶음에만 있는 파일은 합칩니다.** 빠지면 게임이 찾다가 멈춥니다(예: `LYT/SYSTEM.ARC`의 언어별 세이브 배너 `ENG_s_banner.tpl` 등 → 세이브 메모리 확인 화면에서 멈춤). 합친 파일 중 세이브 배너 5개, 4:3 스트랩 화면, 그레그 이름표는 한국어로 채웁니다.
  - 예외: `LYT/MOV/TITLE_LOGO.ARC`는 유럽판 레이아웃을 씁니다. 일본판은 오프닝 자막이 영상에 박혀 있어 레이아웃에 자막 창이 없습니다.
  - 일본판 레이아웃의 후리가나 띠(`NAME_*r`, `*ruby`, `TITLE_text02`)는 투명하게 비웁니다.
- 3D 배경(`MAP/*.acrarc` 안 BRRES)은 유럽판 같은 텍스처 자리에 같은 크기로 넣습니다.
- 유럽판 전용 그림(`tools/assets/eu_only`): 장 제목, 엔딩 이름, 오프닝 자막, 연구소 층 안내판. 장 제목의 빛번짐 마스크(`*ap`)는 한국어 글씨에서 자동으로 만듭니다(배경색과 다른 픽셀 → 3px 부풀림 → 흐림 6 → 밝기 1.3배, 원본 영어 마스크 재현 오차 약 8/255).
- 대화창 이름표(`tools/nameplate.py`): 100×20 텍스처를 돌핀 고해상도에서 늘리면 뭉개져서, 200×40으로 새로 그리고 일본판처럼 굵게 부풀린 마스크를 만듭니다. 창 크기는 그대로입니다.
